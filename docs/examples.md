# 实例

全部来自真实仓库，路径可以核对。正例看结构，反例看代价。

例子会过期：仓库改了，引文和描述就成了新的错误示范。写进这里的每一条都要对着实物核过；实物变了，例子跟着改或删——留着不动的旧例子，比没有例子更坏。

## 三个入口页，正例

### Liquidation `docs/README.md`

开头第一句就交代组织方式：

> 这里按「当前权威 / 研究证据 / 历史来源」组织，不按写文档的时间组织。

这句话解决了两件事：读者知道自己在哪一层，也知道研究材料为什么不算结论。它后面还补了一句：

> 它们用于提供事实、候选方案和来源，不自动升级为当前产品需求或采购结论。

历史那一层结尾写：

> 阶段性交接、旧工作空间说明和旧流程规范不保留：它们描述的做法已经在 `AGENTS.md` 和当前产品文档里，版本追溯由 Git 历史承担。

这就是「归档不是收拾」的正确做法：不再有效的直接说清楚不保留，而不是塞进某个 `archived/` 目录。

### DOOM `docs/README.md`

> 按类型找，不按写作时间找。一个事实只有一个家。

然后是一张三列表：类型 / 位置 / 内容。

| 类型 | 位置 | 内容 |
|---|---|---|
| 蓝图 | `blueprints/product.md` | 产品是什么、为什么做、三个职责、身份连续性、与 DSH / Encephalon 的边界、最低成立状态 |
| 架构 | `development/device-protocol.md` | Device ↔ Gateway 传输契约 |

类型是读者的检索词，内容那一列是一句定位。读者不需要点进去就知道该不该点。

### CloudPrint-SaaS `docs/README.md`

> CloudPrint 的业务与工程文档都收在这一页后面：产品现在到哪一步、为什么这么做、实测数据、各组件怎么跑。

接着是「常走的路径」——五条读者真会问的话，每条直接给文件：

> - 打印不出来、要查打印机和代理 → [打印链路](../print/README.md)。
> - 某个百度接口能不能用、免费额度多少 → [36 项开发范围与百度 API 清单](./baidu-free-api-catalog-2026-10-20.md)。

入口页给路径，不给全量清单；全量清单在分组里按「什么时候点它」标注。

它同时留着上游 OpenStarterKit 的 10 份英文技术文档，这件事本身写明了理由和约束：

> 保留原样的两个原因：一是其中 10 篇登记在 `src/lib/docs.ts` 的 `KIT_DOCS` 清单里，按文件名从 `docs/` 读原文（`KIT_SITE=true` 时作为站点手册发布），文件名和相对路径要固定；二是这些手册描述的上游行为我们不改，翻译它们等于长期维护一份用不到的中文版。

保留也要有理由，理由要指到具体位置。没有理由的保留，半年后没人敢删。

## 反例

下面每一条都真的发生过，现在都修完了。留着是因为失败模式会复发——每条写清改前什么样、现在什么样，才能拿来对照。

### 裸反引号路径

DeepDrink 根 README 的 `## Authority / navigation` 一节有 19 条，全部写成裸反引号路径：

```text
- `docs/architecture.md` — 系统结构
```

在 GitHub 页面上这就是 19 段灰色字符。读者要一条条复制、拼 URL、粘贴。改成 markdown 链接是一次性的工作，之后每个读者都省一次。

现状：这 19 条已全部改成链接。

### 根 README 到 docs 零链接

改前 Nonews 和 Bubble 的根 README 提到了 `docs/`，但没有一条 markdown 链接指向它。从仓库首页出发，走不到任何文档。

这是一个很隐蔽的失败：内容都在，也没写错，但入口不存在。

现状：Nonews 拆出 `## Docs` 一节指向 `docs/README.md`；Bubble 在文档列表末尾补了索引、`CODEMAP.md` 和 `AGENTS.md` 三条。

### 禁止词段落

同一段以「绝对禁止：不得因为你『觉得』某内容敏感，就擅自修改、删除、移动、脱敏、轮换或覆盖它」开头的文字，一度出现在多个仓库的 AGENTS.md 里。现在全库搜「绝对禁止」，0 处。

它的问题不是内容错——「报告，不处置」这个规则本身是对的。问题是它用了全大写、加粗、「绝对禁止」堆在一起，读起来像警报，结果没人读。

同样的意思用正常句子写一遍就够了，Motherland 自己的 README 现在写的是：

> 发现疑似泄露的凭据，报告，不处置。改、删、移动、脱敏、轮换都不该由 agent 替人决定。

### 否定堆叠

SiNS 的 `docs/sins/regions/丘脑.md` 改前是这样开头的：半句定义，然后九个"不"——不拥有 durable truth、不替 Main 做意图推断、不做价值判断、不做优先级、不做方案选择、不做完成决策；接着「仍不是 final request composition owner」「不能据此推断」「不改变 tool 权限」「也不建立第二 context database」。

信息量全部藏在排除法里：读者要把这九个"不"逐个取反，才能拼出它到底做什么。而真正值钱的三件事——它决定 Main 看到什么、它现在在 `system-prompt/assemble` 阶段工作而不是最终组卷位置、完整组卷还差哪一步——被埋在否定句中间。

改法不是删字，是把否定句翻译成事实：

| 改前 | 改后 |
|---|---|
| 不拥有 durable truth | 意图、价值、优先级、方案和完成由 Main 判断（正面点名另一个 owner） |
| 仍不是 final request composition owner | assembly 早于 pre-step 最终接纳，拿不到最终 message batch；完整组卷尚未落地 |
| 不改变 tool 权限或 provider/model 路由 | 消失——权限事实写在子系统页一次就够 |

第三行是被删掉的。它原本挡的是一个没人会犯的误会，却占了整整一句。

现状：这一页后来又压成了现在的短页——只剩职责、指标和两条指针，行为合同在 `architecture/thalamus-design.md`，目标形态在 `blueprints/thalamus.md`。上面那张表记的是那一次改写的取舍。

### 防误读否定，一整段

SiNS `docs/sins/external-projects.md` 改前的开头四句，是这类句子的标本：

> 此页是**外部项目吸收组合的入口**……它不把外部项目的全部实现引入 SiNS，也不替代本地架构和源码的 authority。
> **实际采用与落点**：由 lineage、对应 owning package/system 和现行 Runtime 证明；本页只索引，不复制第二份实现合同。
> 下表中的"采用"包含 **IDEA**，不表示安装了对应第三方软件。
> **集成研究案例，非已采用声明**。

一句定义，三句排除。删掉后三句，读者不会以为这个索引页替代了架构文档，也不会以为表里列的 35 个仓库全都装上了——因为页面本来就在说它们是候选。

改后两个句子就说完了，这是现在的开头：

> 此页记录每个外部项目值得跟进什么、处于什么阶段、下次验证什么、从哪里更新。采用与落点由 lineage 与对应 owning package/system 证明。

> 本页只回答"这个外部项目值不值得继续看、为什么"。它不记录装没装、什么版本、生产是否启用——那些随部署变化，以真实配置与 Runtime 为准。

区别不是长短，是重心：改前用三分之二的篇幅告诉读者"不要误会"，改后三分之二在说"这一页有什么"。

### 否定词云

前面两类句子积到一页，就成了这张图——一份文档的用词统计，出现的每一个词都在排除，没有一个在定义。

![否定词云：一页文档里的高频词，全是否定](assets/negation-cloud.png)

这类文字没有哪一句是错的，错在整页的词表。按它断掉的东西摊开，是四组：

| 断掉的是 | 词 |
|---|---|
| 推论 | 不能推出、不能据此推出、不能据此、不足以证明、不能证明、无法证明、无法说明、只能说明、只能证明、不能简单 |
| 判定 | 不能断言、不能确定、无法断定、不能认定、不能确认、不能承诺、不能保证、还不能、尚不能 |
| 等号 | 不等于、不等同于、不代表、不构成、并不是、不能视为、不能当作、不能当成 |
| 范围 | 不必然、不一定、未必、不能只看、不能仅凭、不能依靠、更准确地说 |

同一个否定，有的必须留。DOOM `docs/hardware/camera-ov5640.md` 这一句是对的：

> 当前 Loopback 未锁定自动曝光与增益，所以上例只作探索性对比，不能换算摄氏度。

它挡的是一个会真的发生的错误：有人会拿这张采样表去换算温度。删掉它，读者会做错事。

另一种否定不挡任何动作，只是作者在替读者预演反驳：

> 这一结果不能代表传感器的真实温度表现，也不必然说明标定无效，不能据此推出该采样方式不可用。

三句排除法，读者读完不知道该做什么、也不知道作者到底确认了什么。它挡住的误读是想象的。

判法：一页里「不能据此」「不足以证明」「不代表」出现两次以上，又找不出一个被它挡住的**具体动作**，就是这一类。改法不是把这些词删干净——上一条保留的句子就带否定——是让每个否定都指向一个动作或一个 owner。剩下的句子改成正面陈述：确认了什么、边界在哪、谁来判断。

### 过程当知识

Nonews 的 `docs/history/visual-review/report.md` 有一张 v1 到 v21 的迭代对照表，记录了每一轮改了什么；同目录还有那张迭代图的 SVG。

写的时候确实是知识。现在没人会读它，而它还在占一个文件位置、还在被索引、还让"docs 里有 16 个文件"这个数字失真。

现状：整个 `docs/history/` 已删。

### 断链的四种形态

同一个问题，四种错法：

- **大小写。** Bubble 的 `docs/method.md` 写 `ORIGIN_LANGUAGE.md`，实际文件名是 `origin-language.md`。Windows 上能打开，GitHub 上是 404。
- **深度。** Bubble 的 `docs/origin-language.md` 写 `../experiments/000-origin.md`，而它在 `docs/` 里，`../` 已经出了仓库。
- **层数。** DOOM 的 `docs/hardware/*.md` 用 `](../../assets/` 指向图片，多退了一层，结果 36 处硬件图片在 GitHub 上一张都不显示。
- **盘符。** SiNS 的 `docs/sins/status.md`、`wishes.md` 用 `D:/SiNS/Workspace/...` 指向自家的会话产物，`plugins/dsh-lifeline/README.md` 用 `D:/Lifeline/README.md`；本机能打开，克隆后什么都没有，GitHub 还会把后者解析成仓库内的 `plugins/dsh-lifeline/D:/Lifeline/README.md`。前三类按「文件在不在」就能查出来，这一类必须按目标形状查。

四种都不是内容错误，是路径错误。改起来都很快，但只有真的扫一遍链接才会发现——人眼看过十几遍都不会注意到。

现状：Bubble 那两处随文件重命名消失（内容并入了 `docs/guides/` 与 `docs/domain/`），全仓已无 `ORIGIN_LANGUAGE` 残留；DOOM 的 36 处已修，另外 67 处图片从 markdown 链接改成 `![]()` 嵌入——GitHub 上嵌入既能显示也能点开，比纯链接多给一样东西。全仓 27 篇、224 条链接、67 处图片，现在断链 0。

### 一个事实五个家

CloudPrint-SaaS 那条「日常不派发实体打印」的规则，改前在五个地方各写一遍：根 README 用一整段，AGENTS.md 用一条，CLOUDPRINT.md 的「验收边界」写一次，roadmap.md 的「阶段边界」写一次，print/README.md 还有整整一节「默认不打印」。措辞各不相同，改一处就得记得改其余四处。

事实重复比模板复制更贵：模板复制只是长得像，重复的事实会分叉——这五句措辞已经各不相同，下次改规则很容易只改到一处。

现状：规则的家定在 `AGENTS.md`，根 README、CLOUDPRINT.md 和 print/README.md 各留一句并指向它，roadmap.md 只留链接。

## 怎么用这些例子

修的时候按这个顺序：

1. **先修链接。** 成本最低，收益最直接，而且修完才能确认内容有没有丢。
2. **再清过程残留。** 计划、报告、进度表，删。
3. **最后动结构。** 分层、合并、拆分都放在最后——前两步做完经常发现结构问题已经小了一半。

反过来做，会在错误的地基上重新分层，然后重新分错一次。
