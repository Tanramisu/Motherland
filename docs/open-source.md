# 开源：把自用项目公开发布

这份规范管一件事：一个原本自用的仓库要公开给任意人看时，内容、文档和历史要改成什么样。自用仓库的默认读者是作者和他的 agent，公开仓库的默认读者是什么都不知道的陌生人。读者换了，写法就得换。

## 不从作者视角写

- 不预设读者知道作者的背景、机器和其它项目。文档从零讲清：这是什么、解决什么问题、怎么用。
- 作者的经历只在作证据时出现（比如「这样用没有被封禁过」），不作叙述框架。「我平时就这么装」「我的两台机器」这类句子，删掉或改成对读者成立的说法。
- 项目状态不写。作者怎么用、在几台机器上跑、承担什么任务，对读者没有用，只暴露个人信息。

## 个人信息：公开面比文件内容大

公开的不只是文件内容，还有四处，一处一处查：

- 文件内容和文件名：真实仓库清单、本机路径、机器名、同步文件夹 ID、凭据，一律不进公开仓。需要登记的留本地文件（如 `REPOS.local.md`），并确认它被 `.gitignore` 排除、从没被提交过。
- 提交历史：内容清干净了，旧版本还躺在历史里。公开前翻一遍历史里的敏感文件。
- commit 元数据：作者和提交者的邮箱也是公开信息。用 noreply 邮箱提交；历史里已经有真实邮箱的，重写历史（改邮箱或孤儿根提交）再公开，不指望「反正没人翻」。

## 公开版和自用部署解耦

同一份源码可以两边用：公开仓放源码和通用文档，部署细节（机器名、路径、账号）留在私有目录。公开仓的文档要让陌生人照着就能做，不引用私有侧的任何东西，私有侧的改动也不依赖公开仓的可见性。

## 入口：一句话、一个开头、一段给 AI 的话

- 仓库简介一句话说清干什么用，大白话，不堆术语。
- README 开头三句内说清是什么、谁会用、怎么用。技术细节进专门文档，README 只给链接，细节不在 README 里展开。
- README 里放一段可复制的话，读者发给自己的 AI，AI 读完仓库自己完成配置或整理。读者不用先学会才能用——这是作者在自己的开源仓库上验证过的用法。

## 文档语言

启用条件：作者不是英语母语者时启用本节，是母语者跳过。

- 默认语言是英语。
- README 必须双语：英语版作默认（`README.md`），再加一份作者的母语版（如 `README.zh-CN.md`），两份在顶部互相链接。两份内容一致，改一份，另一份同批跟上。
- 其余文档按谁会看定：主要给 agent 看的用英语；人类大概率会看的双语。

## 免责与边界集中放末尾

使用前提、风险、免责只写在 README 末尾一节，不散在正文里反复出现。正文讲怎么用，末尾讲出了事谁负责。

## 事实的范围要等于真实范围

写机制，不把某个具体工具写成唯一条件。例子可以具体（「作者用谷歌云盘」），判据要覆盖真实范围（「能同步文件的通道都行」）。写窄了误导读者，写宽了承诺兑现不了。
